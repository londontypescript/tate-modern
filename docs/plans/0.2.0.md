## Contracts the briefs must carry

- **P2 geometry:** each sheet rotates about its own centre, which an offset moves; width and height are
  separate, and the corner radius clamps to the smaller side. Bounds and the animation's safe area use x
  and y extents, so exports, animation and the wordmark's position never clip. Settling uses a 360° turn
  unless a layer is truly symmetric; this also fixes today's jump when a faded square settles
  (`symmetricDelta` assumes 90° symmetry).
- **P2 randomness:** a small integer generator of our own, no dependency, sampled by seed, layer and
  property, so adding a property never shifts the others. Tests pin known outputs.
- **Unchanged by default, proved:** every new field has a neutral value, set explicitly in the MVP
  starter. With the effects off the SVG output is byte-identical: regenerating the three committed assets
  gives no diff. Saved configurations from before a field existed take its neutral value, so they don't
  change when P5 changes the defaults.
- **P3:** an approximation, not a raster match. Gradient strips along the left and bottom tile edges with
  rounded corner patches, above the sheets and under the tile; strength and reach; absent at zero.
  Gradient IDs unique per rendered logo.
- **P4:** starts with a bounded experiment: decorated edges against real overlap highlights, judged still
  and animated. If neither works, #9 closes with the finding.

## How each phase runs

1. The orchestrator writes the brief: the issue, the contract above, the files the subagent may and may
   not touch, done-when. Delicate briefs (P2, P4) get an adversarial ChatGPT Sol 6.1 review first.
2. The subagent works in its own worktree and branch from the latest `main`, test-first, and commits
   only. Shared files (`package.json`, the lockfile, `tsconfig`, the lint config, `src/studio/ui.tsx`) are
   the orchestrator's. Its handoff report: resolved, deliberately deferred, needs a decision.
3. The orchestrator reads every line, lists what the change must defend against and checks each, with
   ChatGPT Sol 6.1's independent review (effort high), then one combined pass.
4. `pnpm gate`; `pnpm build` and the **built** studio (`pnpm preview`): exported SVGs, the animation, an
   older saved configuration; a security check of any new stored input; `temple-bar ready`; push once.
5. CI, the maintainer's yes, `temple-bar merge`.

**Merge window:** `main` requires branches to be up to date. From a push to its merge, nothing else merges,
the README included. If `main` moves anyway, stop and ask; never rewrite a pushed branch.

**Sessions:** at each merge the orchestrator checks its context. If it's heavy, it writes the state on the
next phase's issue and the maintainer starts a fresh session.

## Review record

ChatGPT Sol 6.1, adversarial, effort medium, ~71k tokens (a first run failed at capacity), on a synchronous
and a parallel draft. 16 findings, 15 accepted and folded in: P2 and P4 rated delicate, P3 and P5
involved; the geometry, randomness and unchanged-default contracts; P5 split into two sessions; the release
phase; checks on the built studio; the merge window. Partly rejected: a milestone tracking issue for
progress, since AGENTS.md puts progress on each issue. Its verdict favoured sequential work: lane A (P2-P5)
is the whole critical path. Delegating each phase to a fresh subagent, decided afterwards with the
maintainer, keeps the orchestrator's context small without the cost of parallel lanes.
