## Contracts the briefs must carry

**P1, colours (#38):**

- **The colour fields, all of them:** each entry of `emblem.colours`, `emblem.fadeColour`, `tile.colour`,
  `tile.textColour`, each wordmark run's `colour` and `layout.background`: every saved string the flat renderer
  writes into a `fill`, a `stop-color` or the background `rect`. The facets and the halo use palette constants. An
  inventory test walks the defaults, every starter and the saved fixtures for string fields and fails on any it
  doesn't class as a colour, a choice (`emblem.blendMode`) or text (`tile.text`, each run's `text`), so a colour
  field added later can't go unchecked. It mirrors the numeric inventory in `savedNumbers.test.ts`.
- **Accepted:** `#` and six hex digits, either case (D5), the only form the palette, every starter and the studio's colour input
  produce, kept exactly as written, so the defaults, every starter and every saved fixture come back unchanged
  (`toEqual`) and no output changes. The rule consumes the whole string: whitespace or a newline around a colour
  fails it. Anything else (`url(#…)`, colour names, three-digit hex, other syntaxes, non-strings, missing) takes its
  default, the same field of `defaultLogoConfig`.
- **The arrays:** `emblem.colours` is kept when it is a non-empty array whose every entry is a colour, else it is the
  default array: dropping or repairing single entries would change the alternation silently. The engine's own
  fallback for an empty array (`geometry.ts`, a single palette blue) is then unreachable and goes. A wordmark line's
  `runs` is kept when it is a non-empty array of objects with a string `text`, else it is the default line's runs; a
  run's bad colour takes the default run's at the same line and position, else the wordmark's ink (extra runs, which
  `mergeWithDefaults` lets through, included). The loader's own rule stands: `mergeWithDefaults` takes a saved array
  only at the defaults' length, so a saved `colours` of one or three entries loads as the default array. The engine's
  rule is wider on purpose, since it draws configurations from anywhere; the brief documents and tests the
  distinction, and widening the shared loader would be its own decision.
- **The other strings (D6):** `blendMode` is `normal` or `multiply`, else the default, checked by the same function. A
  glyph's character goes into its SVG id (`tile-letter-0-T`, `glyph-0-0-L`); a character outside `[A-Za-z0-9_-]` is
  written as its code point instead, so a hand-edited text can't produce an invalid id, while every existing output
  (letters only) is unchanged.
- **As P3 of 0.3.0:** the check lives in `sanitizeLogoConfig`, so what's drawn is the checked value and the sliders
  read it the same way; the saved configuration is never rewritten. `generateLayers`, which sanitises the emblem on
  its own, agrees with `buildLogo` on colours and blend mode.
- **The studio path:** `FlatStudio.tsx` previews and exports `config.layout.background`, the raw saved value, and its
  blend and direction toggles read the raw configuration. All take the checked configuration (`used`), so what is
  drawn, shown and downloaded is one sanitised configuration, and a test drives the same function the Download
  button calls, with the background on.
- **What the tests prove:** for each colour field and each bad value (`url(#x)`, `red`, `#fff`, `#12345g`,
  `#1234567`, ` #112233`, a value with quotes and `onload=`, an empty string, a number, `null`, missing, an array, an
  object), with the fade on and off, sheets present and the wordmark's runs populated, so every field reaches the
  output: each sanitised field's exact fallback is asserted on its own, and in every variant, with and without the
  background, every `fill`, `stop-color` and background is `#` and six hex digits or a `url(#…)` to an id inside the
  same SVG, every `style` holds one `mix-blend-mode` declaration and nothing else, and every id is well-formed.
  Break-it evidence: with each check removed, its tests fail with their own messages. `geometry.test.ts` cycles the
  palette with `['a', 'b']` today; it uses two hex colours instead, asserting the same.
- **One colour test:** a pure function in `src/shared/colour.ts`, no React, so the projected follow-up (D7) reuses it
  rather than copying it.
- **Not changed:** how numbers are handled, `mergeWithDefaults`, the projected concept, the assets
  (`pnpm generate:assets` gives no diff), every fixture.
- **Security review** (AGENTS.md): untrusted saved input reaching an exported file. Say what was checked.

**P2, live projected ids (#37):**

- **Own ids:** a live `ProjectedMark` or `ProjectedLogo` without `idPrefix` takes its gradient prefix from React's
  `useId`, made id-safe, exactly as the flat `MarkShapes` does: `lts` and `useId()` with every character outside
  `[A-Za-z0-9_-]` removed. The fixed `lts-projected` fallback (added in b4d22b3) goes.
- **One hook, not two copies:** the flat logic moves into one Node-safe hook in its own file under
  `src/shared/react/` (imported directly, since that folder's `index.ts` pulls in the browser font loader), called
  unconditionally at the existing `MarkShapes` location, an explicit prefix used as given. Only the ids a `url(#…)`
  must find take the own prefix: without an `idPrefix` the shapes still get no ids, as today.
- **Flat output unchanged, shown, not assumed:** the fixtures use an explicit prefix and `halo.test.tsx` checks
  uniqueness and ownership, so neither pins the live prefix's bytes. The handoff shows a before/after byte comparison
  of the same flat tree, fade and halo on, with and without an explicit prefix.
- **Exports unchanged:** with an `idPrefix`, which `standaloneSvg` always passes, the hook's value appears nowhere.
  `renderProjectedSvg` of the default projected configuration, mark and logo, is byte-identical before and after
  (shown in the handoff), and `exportIds.test.ts` passes unchanged.
- **What the test proves:** one page rendered with `renderToStaticMarkup`, holding two live projected marks of
  different configurations and a live projected logo, gradients on: no id appears twice on the page, and every
  `url(#…)` resolves inside its own `<svg>`. Break-it evidence: restoring the fixed fallback makes it fail.
- **The studio's own case:** with "Compare with the live 3D render" on, the projected page shows two live projected
  marks of one emblem; they stop sharing ids.
- **Docs:** the sentence on live components in "Ids and pages with several logos" covers the projected concept too.

**P3, freezing (#36, first part):** 0.3.0's rules, made precise.

- **Two literal configurations** in a new flat module: the 12 October defaults (today's `defaultLogoConfig`, last
  changed in 4dbdc29) and `Irregular (14 Oct)`. Literal means every value written out: no spread, no
  `defaultLogoConfig`, no `defaultWordmarkConfig` (0.5.0 will change the shared wordmark) and no `palette` (colours
  as hex), as the MVP starter already is.
- **Starters use them:** `Original defaults` shows the frozen 12 October copy, `Irregular (14 Oct)` its frozen copy,
  and `Irregular, 150 (14 Oct)` is built from that copy. Nothing renders differently; the studio and the assets
  don't change.
- **Faithful copies, checked while the originals exist:** a test proves each literal `toEqual` the object it
  replaces (today's `defaultLogoConfig`, and the spread `irregularSheets`), which also covers fields that never reach
  the SVG, such as the animation's. These are provenance checks for P3's review only: P4 removes both, since both
  oracles derive from the defaults it changes. What remains immutable afterwards is the committed literals and the
  fixtures rendered from them at P3's base commit.
- **Historical output:** every historical-output assertion in `neutralOutput.test.ts` uses the frozen 12 October
  copy, never `defaultLogoConfig`. The existing fixtures are never regenerated.
- **New fixtures** for the two 14 October starters (mark, wordmark and logo, fixed prefix `lts`), rendered by the code
  at P3's base commit, before any default changes, and recorded as such in the test. They are added once and never
  regenerated. Break-it evidence: changing one frozen value makes a fixture test fail.

**T, the tuning (#36):** the maintainer tunes from W with the existing controls and saves the result under a name,
and sees it saved. The flat studio has no colour controls, so the tuned look keeps today's colours and
`src/shared/palette.ts`. Handover: the named preset's `config` object from the browser's localStorage (key
`lts-logo:presets:v1`, an array of presets, so the name picks the one), with the studio revision used, pasted on #36
or into the session; never the slider labels, which omit the fields without sliders and round to the sliders' steps.
The orchestrator loads it through the pre-change engine, shows its differences from W, and carries that exact object
into the contact sheet for approval. If the tuning needs a value outside a slider's range, or a new control, it stops
there: that is a change to the ranges or the configuration, planned on its own, not folded into P4.

**P4, the defaults (#36, second part), as amended by D9:**

- **The new defaults:** `defaultLogoConfig` becomes `Irregular, 150 (14 Oct)` exactly, written out in full (no spread,
  no shared palette or wordmark). `emblem.colours` keeps two entries: `mergeWithDefaults` rejects a saved list whose
  length differs from the defaults'. A small test pins the animation and background, which no SVG fixture records.
- **One starter, `Default`,** which is `defaultLogoConfig` itself. The studio opens on it, shown pressed, and Reset and

- **The older looks go:** the MVP, the 12 October defaults and `Irregular (14 Oct)`, with P3's frozen copies, their
  fixtures and the studio's `Flat MVP` reference image. `configs.json` stays: it holds saved configurations the loader
  tests read.
- **Today's output is pinned:** the `irregular-150` fixtures, renamed `default`, and new `plain` fixtures rendered
  before any change from the same look with the variation and the halo switched off. The off-switches are proven on
  today's look: byte-identical to `plain` for every seed and every off halo, with sheet sizes, transforms and bounds

- **Other tests are classed assertion by assertion,** never re-baselined to whatever the code gives: a neutral input
  made explicit, a relation kept, a fallback following the new defaults by design, or an old look's output removed.
- **Older saved configurations (D3):** unchanged; they still load with the variation and the halo off.
- **Assets:** `pnpm generate:assets` once, in its own commit; a second run gives no diff, and `exportIds.test.ts`
  proves the studio's download of the defaults matches them.
- **The maintainer's yes before the push,** on the built studio.
- **Docs:** `using-the-studio.md`, `concepts.md`, the README's reference list, and `docs/images/studio.png` retaken
  (D8).
- **Not changed:** the ranges, the sanitiser's rules, the score's literal configurations, the 3D and projected

**P5, the release:** as 0.3.0's, under ADR 0001. A `chore: release 0.4.0` pull request changes only the version in
