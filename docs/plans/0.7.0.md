## Contracts the briefs must carry

- **Layout** (#81, the maintainer's rules): static. The strip is 1200 × 208; the lockup sits in a 120-high layout box
  (385 × 120), its glow painting past that box as it does today; 44 above and below; no side margins. Text is
  optional. With text, the lockup is on the left and the text right-aligned in Exo 2 Light outlined to paths, its
  capitals at the wordmark's cap height and on the baseline of "TypeScript", both taken from the lockup's own data;
  it shrinks only when it would come within 56 of the wordmark. With no text, the lockup is aligned left, centre or
  right (an option). Ink `#f0f6fc` on dark, `#000000` on light. Band off, left or bottom, 14 thick, `edges.ts`'s
  `bandColours` in order. Each rule pinned by a test.
- **Outputs:** the strip, light and dark self-contained SVGs, for READMEs and the website; the Meetup framing, a
  1200 × 675 opaque PNG (and its SVG), the banner fitted inside the Meetup photo's safe rectangle (x 120 to 1080) with
  the band along the photo's edge as on the Meetup photo's band. Text, band and alignment are options on both. One
  renderer draws each framed SVG; the command and the studio both use it, and PNGs rasterise that SVG.
- **Where it lives** (agent decided): its own module, `src/bubble/banner/`, not a slot recipe: every slot recipe must
  have committed assets (`assets.test.ts`) and a fixed canvas, while the banner takes any text. It reuses the lockup,
  `edges.ts`'s band and the typography seam rather than a second layout system. Nothing new in `public/assets/`;
  tate-modern's banner stays in `docs/images/`.
- **Input:** text is escaped by React, never built into strings; output filenames are safe slugs; a character the
  font lacks is an error, never a blank.
- **Freshness:** a test regenerates tate-modern's README banners and compares them with `docs/images/`, so a logo
  change can't leave them stale (break-it evidence).
- **Filenames:** a changed banner gets a new filename (GitHub's image proxy and Safari cache by address); the README
  points at the new files and the old ones are removed. The README keeps #82's shape: no heading under the banner.
- **Parity:** the regenerated banner is shown to the maintainer beside #82's files, with any spacing change from the
  wordmark's kerning fix.
- **The studio's header:** the light banner with the text "Studio" and a bottom band, replacing the header's border,
  drawn live inside the fonts' Suspense; the `<h1>` keeps the accessible name "London TypeScript Studio"; the link
  to the 0.4.0 studio stays; space is kept while the fonts load so nothing jumps.
- **Verification:** the built studio in both themes; the SVGs as standalone `<img>` and resvg PNGs; the Meetup PNG at
  1200 × 675; the README header on GitHub in both themes and at phone width (about 470 px). The maintainer sees each
  UI change before its merge.
- **Files** split along seams within the 400-line cap.

## Decisions

Made with the maintainer on 2 November 2026, before this plan's pull request.

- **D1, scope:** #60 and #70 leave 0.7.0.
- **D2, outputs:** the strip as SVG for READMEs and the website; a 1200 × 675 PNG for Meetup, inside its safe area.
- **D3, options:** text, band and alignment are options on every banner output.
- **D4, the README:** keeps #82's shape, with no `# Intro` heading (amends #81).
- **D5, temple-bar:** if 0.3.0 isn't released when P3 starts, upgrade to the latest 0.2.x and leave 0.3.0 for 0.8.0.
- **D6, the studio's header:** the banner, with the text "Studio".

## How each phase runs

As in [0.6.0's plan](0.6.0.md#how-each-phase-runs): a brief, a subagent in its own worktree that commits only, a
line-by-line review alongside ChatGPT Sol 6.1's (effort high), one combined pass, the gate and the built studio, push
once, CI, the maintainer's yes, `pnpm merge`. The `Reviewed-by` trailer goes on the branch's last commit.
