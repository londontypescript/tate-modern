## Order

P0 → P1 alongside P3 → P2 → P4 → P5

- **P1 beside P3:** no shared files. P1 reads the engine through its public API; its acceptance runs again
  after P3 merges. `package.json` and the lockfile are the orchestrator's, so P1 asks for dependencies.
- **P2 needs P1** (it ranks candidates by the score) and **P3** (both touch `engine/config.ts`).
- **P4 after P2:** both may change `public/assets/` and the fixture tests. Each regenerates the assets
  deliberately in its own pull request (two regenerations, not one). After P4, the scores are rechecked:
  ids must not change pixels.
- **Before P5:** #17 is merged, or the maintainer moves it out.

## Contracts the briefs must carry

**P1, the pipeline (decided first, in the brief):**

- **Renderer:** `@resvg/resvg-js` in tests and CI, no browser. Accepted only after a one-off evidence run
  against the installed Chrome (no browser download, never in tests): normal and `multiply` blending, a
  fade, the halo, at a fixed size on cream. Pass means both per-region pixel agreement within limits set in
  the brief, and the same ranking of a candidate set. If it fails, P1 stops and the maintainer chooses:
  pinned Chromium throughout, or another renderer.
- **Reference:** the WebP is decoded once into a committed lossless crop of the **mark only** (no
  wordmark) plus a committed mask of sheet, tile and background regions, with how they were made recorded.
  Tests read only committed files.
- **Registration:** candidates are the static mark, placed by the central tile's centre and size on a
  fixed canvas, aspect kept, never stretched to their own bounds. Clipping is reported, not hidden.

**P1, what the score means:**

- **Colour** (the ranking objective): CIEDE2000 on sRGB → Lab (D65), over the committed regions, reported
  separately for the sheets and the tile; pixels missing or extra against the reference count against a
  candidate, never drop out. The formula is checked against published test vectors.
- **Shape** (a guardrail): visible-silhouette overlap against the committed mask, not "sheet geometry",
  which a flat image can't reveal.
- **Ranking:** candidates that pass the shape guardrail, best colour first; ties within a stated tolerance
  are shown as ties. Results record the pipeline's versions. Reproducible on the supported setup (macOS
  and CI's Linux), within that tolerance.
- **Proof it's useful:** on one frozen geometry, it ranks colours the maintainer judges better above worse
  ones, and flags opacity extremes and misregistration. Separate break-it evidence for colour, shape and
  registration. Irregular against the MVP is diagnostic only. If the score can't rank usefully, stop
  before P2.
- **Literal inputs:** every configuration a test scores is written out in full, never built from
  `defaultLogoConfig`, so changing the defaults can't change a test.

**P2:**

- **Geometry frozen** during the search; only colour moves: sheet colours, fade colour, opacity, blend
  mode and `tile.colour` (the tile's facet overlays stay). Two or three candidates on one contact sheet
  beside the original, each with its scores. The maintainer picks.
- **Crispness:** the score doesn't measure edge sharpness, so it's judged on the contact sheet. If it needs
  a rendering change, a new issue citing #27 rather than a bigger P2.
- **Flat only:** never `src/shared/palette.ts`, which the 3D and projected concepts share, unless the
  maintainer decides otherwise.
- **If the defaults change:** first freeze `Irregular (14 Oct)` and the old defaults as literal
  configurations (they spread `defaultLogoConfig` today). Every historical-output assertion in
  `neutralOutput.test.ts` uses the frozen copies; the fixtures are never regenerated. Only
  `public/assets/` is.

**P3:** every numeric leaf of the flat configuration, those without sliders included (tile size and
radius, facets, wordmark indents, animation), gets a range and default; non-finite, huge, negative and
missing values are tested. One normalising function, also for whole-number fields (a saved `6.9` layers
shows what's drawn). Sliders show the value used; stored presets aren't rewritten. Assets unchanged.

**P4:** as #24 says, and: the hash API is settled first (sync or async, and every caller), distinct
prefixes for distinct exported **content** (byte-identical exports may share one), UTF-8 input and a
standard digest kept to at least 128 bits, and fixture tests pin the historical `lts` prefix through an
explicit option.

## How each phase runs

As in [0.2.0's plan](0.2.0.md#how-each-phase-runs): the orchestrator's brief, a subagent in its own
worktree that commits only, a line-by-line review alongside ChatGPT Sol 6.1's (effort high), the gate
and the **built** studio, push once, CI, the maintainer's yes, `temple-bar merge`. The delicate brief (P1)
gets an adversarial ChatGPT Sol 6.1 review, then a re-check of the revised brief. The merge window and
session rules there apply.
